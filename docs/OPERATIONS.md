# 运维、数据与审核

本文描述 main 中尚未发布的运维增强。插件版本仍为 v1.4.0；旧 Releases 安装包尚未包含这些新功能。当前行为和限制以本页为准。

## 网页入口与命令

打开插件的 Minecraft 管理面板，进入“运维与数据”，可使用诊断、备份恢复、通知队列、申请审核和日志清理。选择配置组后，诊断、通知和申请聚焦当前组；没有配置组时仍可查看全局诊断和已有备份。

| 默认指令 | 用途 | 权限 |
| --- | --- | --- |
| /mc 诊断 [服务器 ID] | 检查本组目录、RCON、采集器和后台任务 | 完整或白名单管理员 |
| /mc 我的 [页码] | 查看自己名下的白名单 | 本组成员 |
| /mc 申请 | 查看待审核申请 | 成员看自己的，管理员看本组 |
| /mc 通过 <申请编号> | 通过申请并同步 | 完整或白名单管理员 |
| /mc 拒绝 <申请编号> [原因] | 拒绝申请 | 完整或白名单管理员 |
| /mc 取消重启 <服务器 ID 或 all> | 取消尚未发送 stop 的倒计时 | 对应服务器重启管理员 |
| /mc 备份 | 创建插件数据备份，随后在网页下载 | 已核实的 AstrBot 全局管理员 |

这些命令和新增回复模板都可以在“配置与菜单”中修改。新增默认别名与旧自定义指令冲突时，保留旧指令，移除冲突的新默认别名；可在指令设置中查看实际生效值。

## 诊断与后台任务

诊断检查 RCON 认证和查询、白名单读取、服务端目录写入、磁盘剩余空间、spark 文件状态、数据库/WAL 大小、通知数量和后台任务最近成功/错误信息。目录写入检查仅创建并删除一个小型临时文件，不改写白名单。

在线探测与同步、通知投递、保留策略与告警分别运行。未处理的单轮异常会记录错误并按退避间隔重试；成功后继续正常轮询。配置保存与卸载会等待正在使用服务的请求结束，慢服务器查询不再持有整个插件的全局生命周期锁。

磁盘已满时数据库本身可能无法保存通知，所以群告警不能替代系统级磁盘监控。先释放空间，再检查后台任务是否恢复。

## 备份与恢复

升级前先停用插件并保留当前插件数据目录。新增数据库字段不保证旧版代码能继续写入，回退旧代码时应同时恢复升级前的数据目录备份。

手动点击“创建备份”，或将 backup_interval_hours 设为大于 0 的小时数开启定时备份。backup_keep 默认 7 份，恢复前安全备份也计入保留数量；可先下载需要长期保留的备份。备份放在插件数据目录的 backups 文件夹，包含一致性 SQLite 快照、完整插件配置、校验信息，保留编号、用户归属、日志及配置组历史。

备份包含 RCON 配置凭据，只有后台管理员可以下载或恢复；群配置管理员不能创建全局备份。环境变量保存其名称，不会把进程环境中的密码值写入备份。Minecraft 世界、服务端 JAR、模组和其他插件数据不在备份范围。

恢复步骤：

1. 选择本地备份的“预览恢复”，或上传已有的插件备份 ZIP。
2. 核对配置组、服务器、白名单和日志数量。
3. 明确确认覆盖。预览有效期为 10 分钟，且只能使用一次；配置变化后必须重新预览。
4. 插件暂停后台任务，自动创建 before-restore 安全备份，恢复数据库与配置后重新同步白名单。旧待发通知和运行中的重启记录不会从备份继续执行。

重启监控中拒绝恢复。配置保存或恢复应用失败时，会尝试还原原数据库和配置。备份创建、校验和恢复前的安全备份都需要可用空间与正常文件权限；当前数据库已损坏、无法完成安全备份时会拒绝覆盖，应先停用插件并保留整个数据目录后人工处理。

压缩包上限 32 MB，数据库解压上限 128 MB，配置上限 1 MB。只接受插件生成的三文件备份格式，拒绝路径越界、未知文件、校验不一致和不支持的数据库对象。

## 日志与批量白名单

日志可以按操作者、玩家名、动作、开始和结束时间筛选，并导出 CSV/JSON。时间选择按浏览器本地时间输入，日志表格按北京时间显示；日期会转换为 UTC 查询。每次导出最多 10000 条，界面会提示截断；使用日期或搜索分段导出。CSV 防止表格公式被执行，JSON 保留字段原值。

logs_retention_days 与 logs_max_entries 默认均为 0，表示保留全部。启用后每小时按任一超限条件清理；网页可先预览并确认立即清理。清理前可导出日志或创建插件备份；删除日志不等同于立即缩小 SQLite 文件大小。

白名单页支持搜索玩家、UUID、用户 ID、固定编号和分页。可以导出、批量移除以及转移所选条目的归属。原归属用户在转移后失去修改权限，操作会记录审计日志。留空归属表示由管理员管理。

批量导入支持每行一个玩家名、CSV（name,owner）和 JSON 数组。每次最多 500 条，文本不超过 1 MB；正版 UUID 按当前服务器身份模式查询。先预览新增、跳过与错误项，存在错误时不能应用；已有同名同 UUID 条目会跳过，原编号与归属保持不变。预览后本组或共享服相关数据变化时，必须重新预览。批量操作仅作用于当前配置组，共享服仍按并集同步。

## 告警与查询保护

alerts_enabled 默认 false。启用后可监测 RCON 不可用、磁盘剩余空间、spark 采集异常和低 TPS。默认连续 3 轮异常才发送，重复告警间隔 900 秒，恢复后发送恢复消息；重启中的服务器暂不参与告警。

低 TPS 只支持可以解析指标的 spark 模式，默认阈值为最近 1 分钟 TPS 低于 15。原生模式继续完整返回命令文本，不解析或套用 spark 模板。auto 来源没有安装采集器且使用 RCON 时，不会仅因不存在本地报告而发送采集器异常告警。

告警仅发往该服务器关联组中已记录的会话，每个需要接收消息的实际群先发送一次 /mc。alert 和 alert_recovery 模板新增 alert_type、alert_detail 变量，并可使用 server。

query_cache_seconds 默认 3 秒，0 关闭；相同服务器、相同查询类型的并发请求合并，单个调用者取消不会取消其他调用者的查询。启动和周期状态探测直接查询，不受聊天缓存影响。query_user_cooldown 与 query_group_cooldown 默认 0，按需开启冷却；用户按平台账号、群按实际群号计算，多群共用配置时各群冷却独立；RCON 查询并发上限 query_concurrency 默认 8。正版 UUID 成功查询会短期缓存。

## 重启与分级权限

restart_countdown 默认 0，保持立即 stop 的行为。设置倒计时后，在开始及常见时间节点发送群通知，并按 game_broadcast 设置发送游戏内提示。网页展示倒计时、等待关闭、等待启动、检查就绪、同步白名单和最终结果。取消仅限 queued/countdown 阶段，发送 stop 后不能取消。Java 进程仍由自己的启动脚本或进程管理器重新启动。

| 设置 | 权限范围 |
| --- | --- |
| groups[].admin_ids | 本组完整管理权限 |
| groups[].whitelist_admin_ids | 管理白名单、日志、申请、导入与同步；不因此获得重启权限 |
| groups[].restart_admin_ids | 额外授予本组服务器的重启和取消权限 |
| servers[].restart_admin_ids | 非空时，非全局的重启管理员还需匹配此负责人列表，格式为 平台实例ID:用户ID |
| AstrBot 已核实全局管理员 / 后台管理员 | 保留全局管理权限；网页后台可以操作所有配置组 |

需要某账号只管理白名单时，将其加入 whitelist_admin_ids，并从完整管理员 admin_ids 中移除。QQ群主、群管理员头衔仍不自动授予权限。

## 可选申请审核

groups[].approval_required 控制单组审核；根配置 approval_required 为 true 时强制所有组审核。默认关闭，保持原有自助添加流程。

启用后，普通成员添加或修改只生成申请，审核通过前不改写条目或服务端文件。每名成员在一个配置组最多一个待审核申请。管理员通过时重新检查名额、玩家冲突、原条目与归属；原条目已删除、改名或转移时不能套用旧修改申请。

完整或白名单管理员可直接管理条目。成员仍可移除自己的条目，普通成员的查询只返回自己的待审核申请；群聊回复本身对该群可见。跨平台改绑、移除实际申请群或删除配置组会取消失效的待审核申请。

## 通知队列

notification_retry_seconds 默认 30 秒，失败后指数退避；notification_max_attempts 默认 5 次，notification_max_age_hours 默认 24 小时。达到次数上限或有效期的通知进入失败列表，后续消息继续投递。网页可以查看失败原因并手动重新加入队列，重置有效期与尝试次数。

通知是至少一次尝试投递；如果适配器已发送消息但返回失败，重试可能重复发送。请同时检查消息平台的发送日志。删除配置或失效群会话仍按原有规则清理对应通知。
