# 实现依据与设计取舍

本文描述 v1.5.0 的当前实现。旧版兼容范围和修复过程见[更新日志](../CHANGELOG.md)，当前支持范围见[接口适配说明](ASTRBOT_COMPATIBILITY.md)。

- [AstrBot 4.28.0 固定发布包](https://pypi.org/project/astrbot/4.28.0/) 与 [4.29.0 固定发布包](https://pypi.org/project/astrbot/4.29.0/)：隔离验证使用的版本依据。
- [PaperMC 服务端配置](https://docs.papermc.io/paper/reference/server-properties/) 与[命令说明](https://docs.papermc.io/paper/reference/commands/)：白名单、RCON 与查询命令。
- [spark 官方源码](https://github.com/lucko/spark)：TPS 输出与公开 API。
- [spark RCON 异步回复问题记录](https://github.com/lucko/spark/issues/119)：说明不能保证所有环境的异步报告都能从 RCON 返回。

这些资料是接口与实现依据，不表示本插件由上述项目维护或已获其认证。Minecraft、AstrBot、spark 及第三方依赖遵循各自许可证。

## 群和用户的身份

`get_platform_id()` 返回消息平台实例 ID；同一适配器可以有多个实例，所以使用“平台实例 ID + 群号”共同确定作用域。用户归属保存平台用户 ID，不用昵称识别，不把 QQ 群头衔自动当成服务器管理权限。

聊天入口先核实当前会话的全局管理员配置，再把严格布尔管理身份交给核心服务；本群管理员从该群 `admin_ids` 读取。服务层检查条目归属，删除/修改 SQL 写入时再次限定用户或已核实的管理员身份。查 UUID 的等待期间，归属若变化，普通用户的旧请求无法继续修改新归属条目。

归属只代表添加者的平台账号，不是 Minecraft 账号所有权认证。历史导入和跨平台转移后无归属的条目，需要管理员管理。

## 白名单与持久化

初次接管合并同组各服白名单，先完成全部文件读取与冲突校验，再将其作为数据库初始状态。此后 SQLite 是同步依据，不周期导入磁盘旧内容，避免删除条目被离线旧文件重新带入。

条目、审计记录和待同步标记在同一数据库事务中保存，再逐服写文件并尝试重载。各服不能保证同时生效；失败使用待同步状态和后台重试表达。实际改写前备份，写入使用原子替换，默认不覆盖损坏文件。按服务器开启 `whitelist_overwrite` 后，仅允许在完成原文件备份后重建异常文件，目录与链接保护不跳过；初次导入可跳过此服异常内容，手动导入仍严格检查。

`bindings` 使用 `(server, scope)` 联合主键表示当前多对多关系；旧单主键表在事务内迁移。`server_history` 保留首个接管配置组，用于限制首次文件导入，不作为服务器选择锁。每台服同步关联组条目并集，只有同名同 UUID 才能去重；身份冲突会在保存或写入前报错。删除群时归档数据，改群号时保留历史日志原字段并清除旧广播会话。配置提交先暂停旧同步，失败恢复原配置及服务。

## RCON、在线探测和重启

RCON 使用长度前缀、请求 ID、类型与双 NUL 结束。客户端按长度读取，合并同 ID 的多包后再解码 UTF-8；使用只读 `time query gametime` 响应作为界标。服务端应兼容这些 Java RCON 行为。

玩家查询默认 `list`，性能查询默认 `spark tps`，可按服配置。TPS 不从 ping、延迟或日志推算。在线状态通过 RCON 查询确定，不能替代游戏端口或全模组业务健康检查。

启动后的后台循环先并行探测所有已配置服务器，再做按群白名单同步与消息重试；每轮结束后等待 `sync_interval`。因此设置值是轮次等待间隔，不是绝对实时采样承诺。任务暂停、重载和卸载会取消并等待相关操作。

重启只发送 `stop`，由外部脚本启动 Java。旧连接断开后，新 RCON 连续两次玩家查询通过才标记成功。群广播保存到待发送队列；游戏内广播通过 `tellraw` JSON 文本组件发送。适配器静默发送失败不一定能由框架公开返回值识别。

## UUID 与 spark 查询

正版 UUID 通过 Mojang 接口查询，离线 UUID 按 OfflinePlayer 规则生成；网络和文件操作在线程中执行，查询不会阻塞事件循环。

spark 通过 RCON 执行配置的命令，按时间窗口和统计项解析实际返回的指标，不补造 0 或 20。Java agent 与独立指标文件读取仍已移除。针对只写控制台的异步 spark 输出，可在发令前记录日志位置，从本次新增日志获取报告；不会把延长 RCON 等待本身当作保证。具体模式和变量见[查询说明](TPS_VARIABLES.md)。

## 共享与并发

一条配置的 `group_id` 可包含多个实际群号，这些群使用同一数据库作用域。多条配置也可共享物理服务器，各组条目、编号、归属和权限独立；同步时只合并写往该服的内容，不做跨组复制或传递到其他专属服。

相关配置组的首次导入在初始化锁内完成，防止一组先写入空并集覆盖另一组尚未读取的历史文件。初始化不获取其他组锁或服务器锁。每次写入只持有一把服务器锁，在锁内读取当前并集，释放后再处理下一台服务器；不反向获取其他组锁。

`sync_versions` 用于记录变更序号，完成某次写入只清除对应序号的待同步标记；并发变更或取消后的新任务不会被旧任务误标为已同步。`group_sessions` 按实际群记录广播会话，共享服重启结果对全部有效会话去重发送。

## 管理页面与配置生命周期

页面通过 AstrBot 官方 bridge 调用注册的后台接口，并要求后台身份。服务器和群表单、模板、管理员、常规参数都与高级 JSON 共享配置草稿；保存携带版本标识，拒绝旧页面覆盖新配置。读取时递归脱敏密码，保留和清除密码是独立操作。

可纠正的配置错误进入修复状态，仍保留鉴权后的配置 API 与页面，业务服务暂停。修复保存后启动服务。文件权限或其他内部异常不会被伪装成正常服务器状态。

源码只维护 `pages`，构建包复制为 `pages` 与 `views` 兼容不同版本。图标使用根目录 `logo.png`。测试与实际部署的区别见[验证记录](VALIDATION.md)，复现方法见[开发指南](DEVELOPMENT.md)。

## 查询逻辑参考 mc_monitor

2026-10-17 查看用户提供的本地 `mc_monitor` 1.1.0（`monitor.py`、`INTEGRATION.md` 与自检样例）。参考其能力探测、成功命令缓存、来源/耗时展示和明确降级的思路，独立实现 `mc_manager/monitoring.py`，继续使用当前插件的异步 RCON、权限检查、服务器锁与并发控制，未复制其同步 socket 实现。

新增原生只读候选探测、含排队的单服总超时、状态/玩家请求合并、每条结果独立的不可变元数据。未将 `tick query` 的目标速率作为测量 TPS。当前 spark 通过 RCON 发令，空回复时可选读取本次新增控制台日志；不附带 Java agent、不读取旧指标文件。控制台没有请求 ID，新增位置与线程只能提供时间窗口关联，不能绝对证明外部并发请求的归属。

查询返回值保留字符串兼容性；模板从该条结果获取元数据，避免不同服务器或不同缓存请求互相覆盖来源与耗时。后台暂停同时等待共享查询结束。网页变量目录与机器可读 JSON 共用 Python 变量定义，测试验证一致性。

## 各核心数据变量与模板

按用户澄清，将已识别的 TPS 数据拆成变量，而不限定为固定报告布局。默认 messages.tps 只是可编辑的初始文本，raw 可保留原文。独立解析 Paper/Spigot 窗口、Forge/NeoForge Overall/维度、原版目标速率/耗时百分位和自定义性能字段；内存保留原始单位，实体保留回复统计范围，未额外探测系统进程或写入计分板。所有示例按其格式计算自己的预览值，避免在 Forge 或原版模板预览中出现 spark 样例数值。

## 自动配置实现依据

server.properties 仅作为本地参数来源，解析器独立实现，支持 Java Properties 的注释、分隔符、转义、续行和 Unicode 转义，按常见 UTF-8/Latin-1 文件读取。格式依据为 [Java Properties 官方文档](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Properties.html)。目录和文件扫描有深度、数量、类型和大小限制，不执行文件内容，不修改服务端参数。

自动化检查使用临时 server.properties、SQLite、模拟 RCON 与官方网页 SDK，不能替代每一种核心、代理身份转发和容器网络的实机联调。快速配置在参数不齐时给出明确提示，既有手动入口继续可用。
