# 群与游戏消息互通

本功能适用于已绑定的 Minecraft Java 服务端和群聊。总开关及每组开关默认关闭，开启后可分别选择转发方向、事件类型和消息格式，无需另外安装聊天互通模组。

## 在网页开启

1. 打开 **Minecraft 管理面板 → 配置与菜单 → 消息互通**。
2. 在需要使用的群绑定下打开“本组消息互通开关”，总开关会自动开启；选择“群消息 → 游戏”和/或“游戏事件 → 群”。
3. 总开关可统一暂停所有已开启群的互通；再次开启总开关会恢复这些群。
4. 按需选择聊天、进服、退服、死亡事件，调整转发前缀和消息模板，点击“保存并生效”。
5. 在每个实际群里发送 `/mc` 或一条普通文字，让插件记录适配器的真实广播会话。即使只开启游戏 → 群，也可通过普通文字登记会话。已经登记过的群会话会保留。

同一配置填写多个群号时，开关和模板设置共用，但广播会分别发往这些实际群。各群需要登记自己的会话。绑定同一服务器的不同配置组可独立决定是否启用互通。

## 转发范围

| 来源 | 目标 |
| --- | --- |
| 群 1 绑定 server1、server2 | 群 1 普通消息只广播至 server1、server2 |
| 群 2 绑定 server1、server3 | 群 2 普通消息只广播至 server1、server3 |
| server1 的游戏事件 | 向开启游戏 → 群的群 1、群 2 转发 |
| server2 的游戏事件 | 仅向开启游戏 → 群的群 1 转发 |

按平台实例 ID 和实际群 ID 匹配，群消息不会直接转发到其他群，也不会经由共享服务器传递到其他服务器。机器人自身的消息会被跳过。

## 群 → 游戏

仅转发消息里的普通文字部分，图片、语音、文件、引用消息原文不作内容转发。消息使用固定的 `tellraw @a` 命令和 JSON 文本组件广播，昵称、正文及花括号都作为文本数据处理。

- 默认转发普通文字；如果只想转发指定消息，可将本组“群消息转发前缀”设为 `#mc`，之后发送 `#mc 大家好`。
- 前缀会从正文移除。移除后以 `/`、`!`、`！` 开头的指令不转发。
- 原生 `/mc`、`mc` 及配置的 MC 主指令别名不转发；该功能不授予群成员执行控制台命令的权限。
- 默认同一实际群内每位用户冷却 2 秒，可在网页改为 0 关闭。
- 如果适配器提供消息 ID，同一平台、同一实际群的重复消息在 60 秒内不会重复发送。
- 服务器处于本插件的重启监控中时，发往该服的群消息会跳过。

### § 染色码

群 → 游戏模板和群消息正文都支持 `§0`～`§f` 颜色、`§k`～`§o` 样式、`§r` 重置，以及 `§x§R§R§G§G§B§B` 十六进制格式。旧核心是否接受十六进制颜色取决于其文本组件支持情况。

默认模板：

```text
§b[群 {group}] §f{nickname}§7: §r{message}
```

例如 `§b` 青色、`§a` 绿色、`§c` 红色、`§l` 加粗。颜色码会转换为游戏文本组件；发到群内的游戏消息则去掉颜色码，以普通文字显示。

## 游戏 → 群

插件按间隔读取各服新增日志，默认读取服务端目录内的 `logs/latest.log`。在“服务器与群聊 → 编辑服务器”可修改相对路径与日志编码，支持 `utf-8` 和 `gb18030`。

支持标准英文 Java 服务端日志样式中的：

- `<Steve> 消息`、`[Not Secure] <Steve> 消息`；包括常见 Paper 异步聊天线程日志。
- `Steve joined the game` 和 `Steve left the game`。
- 已识别的原版英文死亡消息，如 `Steve was slain by Zombie`、`Steve hit the ground too hard`、`Steve drowned`。
- 常见 Forge 日志附加的 `[minecraft/MinecraftServer]` 分类前缀。

只解析可信格式的服务端 INFO 行，忽略 RCON 回显、普通控制台输出和插件标签消息。玩家在聊天正文中说“Alex joined the game”仍只会作为聊天转发。

**日志边界：** 启用、重新加载或保存配置后，会跳过当时已存在的历史日志；日志文件轮转、截断和常见原地重写会重新定位读取。不存在的日志会等待创建。第三方聊天插件、自定义昵称布局、非英文事件和自定义死亡文本可能无法识别；未写入日志的事件无法转发。这里验证的是日志样例解析，不代表已实测所有核心与版本。

AstrBot 必须能读取日志文件；Docker 需要同时挂载服务端日志目录。RCON 只用于群 → 游戏，不负责被动接收游戏聊天。

## 模板与变量

在“消息互通 → 消息格式”修改以下模板，也可编辑配置中的 `messages` 对象。所有模板均支持这些字段；不适用于当前方向的值为空。

| 模板键 | 用途 | 默认效果 |
| --- | --- | --- |
| `bridge_to_game` | 群消息广播到游戏 | `[群 100] 昵称: 内容`，带 § 样式 |
| `bridge_chat` | 游戏聊天到群 | `[服务器] <Steve> 内容` |
| `bridge_join` | 玩家进服到群 | `[服务器] Steve 加入了游戏` |
| `bridge_leave` | 玩家退服到群 | `[服务器] Steve 离开了游戏` |
| `bridge_death` | 玩家死亡到群 | `[服务器] 原始死亡文本` |

| 变量 | 意义 | 适用方向 |
| --- | --- | --- |
| `{server}` | 服务器显示名称 | 双向 |
| `{server_id}` | 服务器配置唯一 ID | 双向 |
| `{group}` | 实际群号，非配置组 ID | 双向 |
| `{nickname}` | 群消息发送者昵称 | 群 → 游戏 |
| `{user}` | 群消息发送者账号 ID | 群 → 游戏 |
| `{player}` | Minecraft 玩家名 | 游戏 → 群 |
| `{message}` | 群正文、游戏聊天正文，或完整的进退服/死亡事件文本 | 双向 |
| `{event}` | `chat`、`join`、`leave` 或 `death` | 双向；群 → 游戏为 `chat` |

字面花括号需要写为 `{{` 和 `}}`。死亡消息默认保留英文原文，可用模板添加中文前缀；不会自动翻译正文。

## 配置字段

完整默认配置见 [config.default.json](../config.default.json)，有服务器与群的示例见 [config.example.json](../config.example.json)。

| 配置位置 | 字段 | 默认值 |
| --- | --- | --- |
| 根配置 | `bridge_enabled` | `false`，总开关 |
| 根配置 | `bridge_poll_seconds` | `1`，1～60 秒 |
| 根配置 | `bridge_max_chars` | `500`，32～2000 字符 |
| 根配置 | `bridge_cooldown_seconds` | `2`，0～300 秒 |
| `servers[]` | `bridge_log_path` | `logs/latest.log`，本服内相对路径 |
| `servers[]` | `bridge_log_encoding` | `utf-8`，可选 `gb18030` |
| `groups[]` | `bridge_enabled` | `false`，本组开关 |
| `groups[]` | `bridge_to_game` / `bridge_to_group` | 均为 `true` |
| `groups[]` | `bridge_chat` / `bridge_join` / `bridge_leave` / `bridge_death` | 均为 `true` |
| `groups[]` | `bridge_prefix` | 空字符串，转发普通文字 |

开启开关的最小修改：

```json
{
  "bridge_enabled": true,
  "bridge_poll_seconds": 1,
  "bridge_max_chars": 500,
  "bridge_cooldown_seconds": 2
}
```

将上方字段合并到现有根配置，并在已有的目标 `groups[]` 项中设置 `"bridge_enabled": true`。不要用此片段替换包含服务器、群绑定的完整配置。

## 运行状态与故障排查

在 **运维与数据 → 环境与后台任务 → 重新诊断** 查看消息互通队列、成功/失败/丢弃计数、各服日志读取状态和最近错误。

- 群能发到游戏、游戏不能发到群：检查日志挂载、编码、游戏 → 群开关、事件开关和该实际群是否登记会话。
- 游戏能发到群、群不能发到游戏：检查 RCON、群 → 游戏开关、转发前缀及冷却。
- 日志读取正常但事件未转发：确认开启后新增日志符合上述格式；可携带脱敏后的原始日志行反馈。
- 短时间消息过多或网络故障：互通队列最多 200 条，超过 30 秒的消息丢弃，单条正文按字符上限截断，游戏命令还会按 RCON 包大小截断。聊天采用尽力投递，不落入重启/告警的持久重试通知队列，避免恢复后重复刷屏。

保存配置与卸载会停止并等待互通后台任务；更新配置时使用新实例和新日志位置。无需开放额外 TCP/HTTP 接收端口。

## 参考实现分析

本次参考 [WindClear-VC/astrbot_plugin_Rcon_minecraft](https://github.com/WindClear-VC/astrbot_plugin_Rcon_minecraft)，核对提交 `c1d88374c7c032578696ed18fb13d193eaf058d8`，日期为 2026-10-17。

该仓库的 `main.py` 通过 `asyncio.start_server` 监听 TCP，接收按行分隔的 `player`、`message`、`server` JSON 或 `PlayerName: message` 纯文本，依赖服务端额外的消息推送模组，再将聊天发送到 `bridge_qq_group`。它每 10 秒用 `list` 比较玩家集合，但进退服结果仅写入插件日志；所查代码未见普通群消息转发处理器、死亡事件转发或 `§` 文本组件转换。其 `bridge on/off` 分支只修改内存标志，已启动的 TCP 处理器未按该标志中断转发。README 的功能描述应与当前源码区分。

本插件保留 MIT，独立编写日志读取、事件识别、消息队列、颜色转换和 AstrBot 群监听；未复制该仓库源码。利用本插件已有的服务端目录和 RCON 配置，省去额外服务端模组及监听端口，并沿用已有的多群、多平台和共享服隔离。
